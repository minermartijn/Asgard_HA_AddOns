# Evidence of actual adoption and maintenance

If you apply to a developer support or open-source sponsorship program, prefer verifiable impact over polished claims.

## What to document

- Links to issues reported by **other** Home Assistant users and the fixes made.
- GitHub PRs from real external contributors, with credit preserved.
- Tested Home Assistant / Python / architecture combinations, with dates.
- Versioned releases and their changelogs.
- Links to public community discussions and user feedback (with permission where appropriate).
- Public issue response and maintenance history.

## What not to do

- Do not count the maintainer's test installations as external adoption.
- Do not invent download counts, contributor numbers, stars or testimonials.
- Do not collect telemetry or user secrets solely to show adoption.
- Do not expose user logs, home IPs, access tokens, private URLs or household data.
